# Supabase

Database schema, reference data and verification for NEXA.
Design and table reference: [`docs/DATA_MODEL.md`](../docs/DATA_MODEL.md).

```
supabase/
  migrations/   ordered SQL migrations (schema, RLS, views, cron, M1 market in PL/pgSQL)
  updates/      idempotent copies of later migrations for update-to-latest.sql
  seed.sql      reference data (sectors, 15 AI companies, bonds, index, catalogues, invite codes)
  tests/        local verification on a throwaway PostgreSQL cluster
  tools/        generator for the table/ER sections of docs/DATA_MODEL.md
```

## Link a project and push

Requires the [Supabase CLI](https://supabase.com/docs/guides/cli) (`pnpm dlx supabase ...` works too).

```bash
supabase login
supabase link --project-ref <project-ref>     # asks for the database password

supabase db push                              # applies supabase/migrations/*.sql
supabase db push --include-seed               # ... and runs supabase/seed.sql
```

`seed.sql` is idempotent, so running it again is safe. It does **not** contain `game_config`;
generate and apply that from `src/config/balance.ts`:

```bash
pnpm db:config        # writes the config seed (see package.json)
```

Local Supabase stack instead of a hosted project (needs Docker):

```bash
supabase start
supabase db reset     # migrations + seed.sql
```

## One-time setup after the first push

1. **First admin** (there is no client-writable admin flag). In the SQL editor:

   ```sql
   insert into public.admin_users (user_id, note)
   select id, 'owner' from auth.users where email = '<your email>';
   ```

2. **Market jobs (M1)**: nothing to configure. The market runs inside Postgres: `pg_cron` calls
   `public.market_tick()` every 5 seconds and `public.run_due_jobs()` every minute (quarter close, bond
   maturities, calendar, rich list snapshots, daily maintenance). The first bootstrap also runs the one-time money
   genesis (closed money system, 10 Mrd. EUR) and seeds the 120 AI tycoons. The migrations enable `pg_cron` when the project offers it and remove
   the old edge-function jobs of migration 1600. Without `pg_cron`, call both functions yourself.
   Admin RPCs: `admin_set_paused(bool)`, `admin_run_tick()`, `admin_close_quarter()` (moves game time to the end of
   the running quarter and closes it).

3. **Invite codes**: `seed.sql` creates placeholder codes (`NEXA-...`). Replace them before inviting anyone.

4. **Auth settings**: sign-up passes `invite_code`, `age_confirmed` and optionally `nickname` in
   `options.data`. A missing or invalid code makes the sign-up fail (trigger `handle_new_user`).

## Updating an existing project (SQL Editor only)

Paste `supabase/update-to-latest.sql` into the Supabase SQL Editor and run it. It is safe to run any number of
times: every schema change is idempotent, `game_config` is overwritten with the values from `balance.ts`, the
`pg_cron` jobs are (re)scheduled and `public.market_bootstrap()` starts the market (price history only once).
New projects use `setup-all.sql`. All three files are generated by `bash scripts/build-setup-sql.sh`; every new
migration needs an idempotent copy in `updates/` (see `updates/README.md`).

## Local verification (no Docker, no CLI)

Needs only the PostgreSQL 16 server binaries.

```bash
supabase/tests/verify_local.sh
```

The script creates a temporary cluster, installs a minimal Supabase stub (roles `anon`, `authenticated`,
`service_role`, schema `auth`, `auth.uid()`), applies all migrations and `seed.sql` (twice, to prove
idempotency) with `ON_ERROR_STOP`, and runs the assertions in `tests/[1-9]*.sql`:

| File                        | Checks                                                                                                                                            |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `10_structure.sql`          | RLS on every table, no privileges for `anon`, write/execute allowlists for `authenticated`, FK indexes, unit conventions, game calendar incl. DST |
| `20_signup_ledger.sql`      | sign-up trigger (invite, age, profile, accounts, starting capital), ledger immutability and balance checks, rate limit, idempotency               |
| `30_rls.sql`                | player A vs. player B vs. `anon` vs. `service_role`: private rows, forbidden writes, internal tables, public views, insider and friend rules      |
| `40_seed.sql`               | seed counts and consistency (15 companies, 5 sectors, bonds, index, achievements, ...)                                                            |
| `50_m1_market.sql`          | M1: bootstrap and price history (counts, OHLC, contiguity), ticks, sessions and the 22:00 bell, read RPCs                                         |
| `51_m1_day.sql`             | M1: one simulated day (17 280 ticks) on a throwaway copy of the database; prints daily range per size class and tick times                        |
| `52_m1_trading.sql`         | M1: orders, idempotency, fee, tax and loss pot, limits and order book, cancel, fills by the tick, error keys, XP, unlocks, tutorial, rate limit   |
| `53_m1_bonds_vault.sql`     | M1: bond coupons and redemption over admin quarter closes, run_due_jobs, admin pause, vault                                                       |
| `54_m2_fractional.sql`      | M2: fractional shares (millionths), orders by amount, minimum order value, 99.9 % rule, `*_e6` JSON shapes                                        |
| `55_m1_security.sql`        | M1/M2: execute rights (authenticated/anon), internal functions, player isolation                                                                  |
| `56_m2_money.sql`           | M2: closed money system (genesis, mint closed, invariant after trades, coupons, quarter closes), treasury flows, basic income factor              |
| `57_m2_names.sql`           | M2: name filter with false-positive traps and leetspeak, reserved names, sign-up, `check_nickname`, `change_nickname`                             |
| `58_m2_rich_list.sql`       | M2: AI tycoons, `get_rich_list` (scopes, me/next, 24 h changes), rank news                                                                        |
| `59_m2_missions.sql`        | M2: mission assignment and idempotency, locked features, progress and claims, quick replacement, `track_event`, daily check-in and streaks        |
| `60_m2b.sql`                | M2b: avatars, daily reward cycle and freezes, skills and points, AI job board determinism, applications, contracts, wages, raises, employer side  |
| `61_m3c_levels_markets.sql` | M3c: new XP curve and level protection, player orders move prices in euros, holdings premium, AI weight, bond impact                              |
| `62_m3c_companies.sql`      | M3c: founding rules, places, quarter close (money, quality, awareness, XP), distress, deposit/withdraw, upgrade, net worth, RLS                   |

It exits non-zero on the first failed assertion and removes the cluster afterwards. A full run takes about
1.5 minutes (most of it is the simulated day). `NEXA_MIGRATIONS_UPTO=20261110001600 supabase/tests/verify_local.sh`
simulates an older database: only migrations up to that timestamp, then `update-to-latest.sql` (twice) before the
M1/M2 assertions. `NEXA_MIGRATIONS_UPTO=20261111000500` simulates a project that already has M1.
`NEXA_FIXTURE_DIR=$PWD/src/features/game/__fixtures__` also writes one real response of every RPC (`tests/fixtures.sql`)
for the frontend contract test.

| Variable       | Default                      | Purpose                                      |
| -------------- | ---------------------------- | -------------------------------------------- |
| `PG_BIN`       | `/usr/lib/postgresql/16/bin` | directory with `initdb`, `pg_ctl`, `psql`    |
| `NEXA_PG_DIR`  | `mktemp -d`                  | work directory for the cluster               |
| `NEXA_PG_PORT` | `54329`                      | port                                         |
| `NEXA_KEEP`    | `0`                          | `1` keeps the cluster running for inspection |

When started as root the script runs the server as the `postgres` OS user, or inside a user namespace
(`unshare`) if that user cannot reach the work directory.

## Regenerating docs/DATA_MODEL.md

Sections 3 (tables) and 4 (ER diagrams) are generated from a live database:

```bash
NEXA_KEEP=1 supabase/tests/verify_local.sh
python3 supabase/tools/gen_data_model.py "postgresql://postgres@127.0.0.1:54329/nexa_verify"
# afterwards stop the cluster: pg_ctl -D <NEXA_PG_DIR>/data stop
```

New tables need a German one-line purpose in `PURPOSE` inside the tool and an RLS class in
`migrations/20261110001400_triggers_rls_policies.sql` (that migration fails if a table is unclassified).
For later schema changes add new migration files; do not edit applied ones.

## Conventions in one glance

- Money `bigint` cents (`*_cents`), prices `bigint` with 1 EUR = 10000 (`*_e4`), rates in basis points (`*_bps`).
- RLS on every table. Clients read; all game writes go through `SECURITY DEFINER` functions.
- New functions are not executable by anyone but the owner and `service_role` until a migration grants `EXECUTE`.
- Every money movement goes through `public.ledger_post()`.
